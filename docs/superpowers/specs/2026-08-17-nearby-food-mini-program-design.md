# “最想吃啥”微信小程序设计规格

日期：2026-08-17  
状态：已确认，待实施计划

## 1. 产品目标

“最想吃啥”是一款面向公众发布的微信小程序。用户打开后授权定位，小程序优先展示其当前位置附近、由近到远排列的个人收藏餐馆；附近没有收藏，或用户主动切换到推荐模式时，小程序根据品类、关键词、预算、距离与出行时间推荐附近餐馆。

首版以“个人想吃清单 + 附近推荐”为核心，不依赖读取美团或大众点评账户收藏的非公开接口。用户通过分享链接或站内搜索建立清单。未来获得正式数据授权后，可新增官方账号同步或榜单信号，但不得改变现有用户数据边界。

## 2. 首版范围

### 2.1 包含

- 微信身份识别与用户数据隔离。
- 首次定位授权，以及拒绝定位后的手动地点选择。
- 个人收藏首页，默认由近到远排列。
- 公里半径筛选：1、3、5、10 公里，默认 5 公里。
- 步行、骑行、驾车方式及出行时间筛选。
- 从美团、大众点评、高德的常见门店分享链接导入。
- 站内按门店名称或任意餐饮关键词搜索。
- 同名多分店的单选或多选收藏。
- 固定品类快捷入口及任意关键词输入。
- 可选预算和营业状态筛选；营业状态仅在数据源明确返回时生效。
- 推荐结果、透明推荐理由、收藏、地图导航和单店分享。
- 好友打开分享卡片后主动加入自己的清单。

### 2.2 不包含

- 自动读取美团或大众点评账户收藏。
- 截图 OCR 批量导入。
- 抓取、复制或冒充大众点评必吃榜、高德扫街榜。
- 公开收藏清单、关注、动态、评论或社区排行榜。
- 用户持续位置轨迹记录。
- 支付、团购、排队或订座。

## 3. 数据源原则

首版唯一公共餐馆数据源为高德 Web 服务 API。使用其地点关键字搜索、周边搜索和路线能力获取可用的门店名称、地址、坐标、品类、距离、评分、人均、标签和图片。字段是否展示以接口实际返回为准。

评分、人均、营业状态或图片缺失时，小程序隐藏对应信息，不推断或伪造。美团、大众点评和高德分享链接仅作为门店匹配线索；链接中的数据必须通过高德 POI 匹配和用户确认后进入收藏。

第三方 API Key、签名材料与推荐权重只保存在云端。客户端不直接调用需要保密凭证的第三方接口。

## 4. 核心体验

### 4.1 首次打开

1. 展示定位用途说明：位置仅用于查找附近门店和计算出行距离。
2. 用户允许定位后进入收藏首页。
3. 用户拒绝定位时，可搜索并选择一个地点作为本次查询中心。
4. 小程序不在后台持续采集位置，也不保存位置轨迹。

### 4.2 收藏优先首页

1. 读取当前用户收藏和当前查询中心。
2. 在选定半径内查找收藏分店。
3. 结果严格按距离升序排列，不计算质量综合分。
4. 门店卡片展示分店名称、距离、可用的出行时间和公开信息。
5. 用户可切换半径、出行方式或时间条件。
6. 没有附近收藏时展示推荐入口；有收藏时也保留“换成附近推荐”的主动入口。

### 4.3 分享链接导入

1. 用户粘贴或通过微信分享入口传入美团、大众点评或高德门店链接。
2. 云函数识别链接来源，安全解析跳转目标，并提取门店名称、城市、地址或分店线索。
3. 以线索查询高德 POI。
4. 唯一匹配时展示单店确认页。
5. 存在同名分店时展示多选列表，每项包含分店名、地址、商圈和距当前或手选地点的距离。
6. 用户可选择一个或多个分店批量加入收藏。
7. 已收藏分店显示“已加入”，不得生成重复记录。
8. 批量操作部分成功时，逐项显示成功、已存在或失败状态。
9. 无法解析链接时，使用可提取的店名转入站内搜索；完全无法提取时允许用户手动输入。

### 4.4 站内搜索收藏

1. 用户输入门店名称或关键词。
2. 系统结合当前城市和位置搜索高德 POI。
3. 搜索结果按相关性和距离展示。
4. 同名分店采用与链接导入相同的多选、去重和批量反馈规则。

### 4.5 附近推荐

1. 用户选择固定品类，输入任意关键词，或选择“随便吃”。
2. 用户可选预算、公里半径、步行/骑行/驾车方式、最长出行时间和营业状态。
3. 系统先按硬条件获取候选门店，再计算推荐分。
4. 返回 3 至 10 家门店；不足 3 家时按实际数量展示。
5. 每个结果展示推荐理由，并支持加入收藏或打开地图导航。
6. 无结果时建议逐步放宽时间或半径，只有用户确认后才重新查询。

### 4.6 单店分享

用户可将一张公开门店卡片分享给微信好友。好友只能看到该门店公开信息，并可主动点击“加入我的想吃”。分享不会暴露分享者身份、完整清单或其他私密数据，也不会自动替好友收藏。

## 5. 推荐规则

### 5.1 候选生成

- 公里半径是高德周边搜索的候选边界。
- 品类或关键词、预算及可靠的营业状态是硬筛选条件。
- 先按直线距离和基础质量筛出最多 20 家候选，再为靠前候选计算路线时间，以控制路线 API 调用量。
- 最长出行时间作为二次筛选条件；无可靠路线时间时，结果必须标明仅按距离估算，不得声称满足时间限制。

### 5.2 综合分

- 品类或关键词匹配：35%。
- 距离或所选方式的出行时间：30%。
- 高德评分：20%。
- 预算匹配：10%。
- 信息完整度：5%。

任一字段缺失时移除该维度，并按剩余维度重新归一化。并列结果依次按距离更近、评分更高、名称稳定排序，保证相同输入得到稳定结果。

推荐理由必须来自实际参与排序的信号，例如“符合潮汕牛肉火锅、步行约 12 分钟、评分 4.6”。不得显示未参与计算或不存在的数据。

## 6. 系统架构

采用微信原生小程序、腾讯云 CloudBase 和高德 Web 服务 API。

### 6.1 小程序客户端

- 定位授权、手动地点选择和筛选交互。
- 收藏首页、导入确认、搜索、推荐和单店详情页面。
- 仅传递业务输入，不传递用户 OpenID 或第三方密钥。

### 6.2 CloudBase 云函数

按单一职责拆分：

- `favorites`：读取、批量新增和删除当前用户收藏。
- `place-search`：高德关键字与周边搜索适配。
- `place-routes`：路线时间批量计算与限流。
- `link-import`：分享链接白名单校验、解析和 POI 匹配。
- `recommend`：候选生成、缺失字段处理、打分和理由生成。
- `share-place`：生成和解析不包含私密信息的门店分享参数。

每个云函数从可信调用上下文获取 OpenID。客户端传入的任何用户标识均忽略或拒绝。

### 6.3 数据库集合

- `users`：用户设置、默认半径、出行方式和预算偏好。
- `favorites`：OpenID、POI ID、个人备注、来源和创建时间；以“OpenID + POI ID”建立唯一性约束语义。
- `places`：高德 POI 公共缓存、来源更新时间和字段完整性。
- `imports`：当前用户的链接导入状态、候选与错误原因；原始链接按最短必要期限保留。
- `recommendation_events`：当前用户的收藏或不感兴趣反馈，仅供其个人推荐使用。

`favorites`、`imports` 和 `recommendation_events` 采用仅创建者可读写规则。涉及批量写入、去重和外部调用的操作必须通过云函数完成。

## 7. 安全、隐私与合规

- 收藏、导入记录和推荐反馈按微信用户严格隔离。
- 服务端不接受客户端指定数据所有者。
- 第三方密钥存放于云端环境变量或密钥管理中。
- 链接解析只允许已支持的 HTTPS 域名，限制重定向次数、响应大小和超时，防止服务端请求伪造。
- 不保存第三方账号密码、Cookie 或登录态。
- 不抓取非公开榜单、评价或账户数据。
- 位置仅用于当前附近查询；用户偏好与地点选择可删除。
- 用户删除收藏后立即从个人清单移除；用户注销时删除其所有个人集合记录。
- 小程序隐私说明必须列明位置、收藏、导入链接和推荐反馈的用途与保存方式。

## 8. 异常与降级

- 定位拒绝或失败：手动选择地点。
- 高德超时：优先展示未超过缓存有效期的数据并标注更新时间；没有可用缓存时显示重试。
- 高德限流：指数退避、短期缓存和用户可理解的稍后重试提示。
- 链接无法识别：店名搜索或手动输入。
- 同名门店：显示多选分店列表，不自动猜测具体分店。
- 批量收藏部分失败：保留已成功项目，逐项反馈，不整体回滚用户已确认的成功项。
- 缺失评分、人均、图片或营业状态：隐藏字段并重新归一化排序权重。
- 无收藏或推荐结果：提示扩大半径或时间；变更条件前取得用户确认。
- 路线时间不可用：展示距离，并明确标记时间未计算。

## 9. 测试与验收

### 9.1 权限

- 用户 A 无法读取、修改或删除用户 B 的收藏、导入记录和反馈。
- 伪造 OpenID 或数据所有者参数不能越权。
- 分享参数只能解析公开 POI 信息。

### 9.2 收藏与导入

- 附近收藏按距离严格升序。
- 美团、大众点评和高德支持的常见分享链接均能进入匹配确认流程。
- 无法解析的链接可靠降级到搜索或手动输入。
- 同名分店可单选或多选。
- 重复分店不重复写入。
- 批量部分成功时反馈准确且可重复执行。

### 9.3 推荐

- 固定品类、自由关键词和“随便吃”均能产生候选。
- 半径、预算、出行方式和最长时间按定义生效。
- 缺失字段后权重正确归一化。
- 边界距离、并列结果和相同输入的排序稳定。
- 推荐理由与实际打分信号一致。

### 9.4 异常

- 定位拒绝、API 超时、限流、空结果、路线失败和缺失字段都有可操作的降级界面。
- 高德 Key 不出现在小程序包、日志或客户端网络参数中。
- 缓存数据展示更新时间，不冒充实时结果。

## 10. 发布顺序

1. 建立 CloudBase 环境、数据库权限与云函数接口。
2. 完成定位、手选地点和收藏优先首页。
3. 完成站内搜索、单店/多分店收藏与去重。
4. 完成分享链接解析与降级搜索。
5. 完成推荐、路线时间、理由生成和异常降级。
6. 完成单店分享、隐私说明、自动化测试和微信审核材料。

后续迭代可增加截图 OCR、个人口味学习、主动分享清单，以及获得正式授权后的第三方收藏同步和榜单信号。

## 11. 成功标准

- 新用户无需理解数据源即可在首次会话完成定位、搜索并收藏一家门店。
- 有收藏的用户打开首页后能直接看到附近收藏及其由近到远排序。
- 无附近收藏的用户能在一次推荐流程内得到可解释结果并发起导航或收藏。
- 用户之间不存在可复现的数据越权路径。
- 第三方接口不可用时，核心收藏数据仍可访问并给出明确降级状态。
